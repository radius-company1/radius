## Хостинг: подтверждённое и неизвестное

Новая версия сейчас: https://radius-company1.github.io/radius/lexicom/ — HTTP 200, `Server: GitHub.com`. Vite base `/radius/lexicom/`. Скрипт `scripts/deploy-lexicom.sh` собирает `lexicom-site/dist` и копирует его в `lexicom/`; затем публикация связана с git-репозиторием. Этот скрипт здесь НЕ запускался.

В проверенной копии нет CNAME и workflow YAML. Git remote HEAD совпал с 9005a4d. Настройки Pages в панели GitHub (точная ветка/папка/режим публикации, enforce HTTPS) не удалось подтвердить: публичный `GET /repos/radius-company1/radius/pages` вернул 404 без авторизации. Это не доказательство отсутствия Pages. Не выдаём предполагаемые `main / root` за проверенную настройку. Перед будущей публикацией нужен просмотр Settings → Pages с доступом владельца.

Действующий https://lexicom.ai/ — HTTP 200; DNS A `82.151.110.244`; заголовки `Apache/2.4.41 (Ubuntu)`, `X-Powered-By: Next.js`. Это признаки текущего стека, не доказательство доступа к Apache и не установление хостинг-провайдера. DNS только прочитан.

Старые robots.txt и sitemap.xml указывают на `https://localhost:3000`. Реальный `/sitemap-0.xml` доступен и содержит URL lexicom.ai. Снимки сохранены в `evidence/`. Старый сайт оставлен работающим.

GitHub Pages — статический хостинг; пользовательских правил серверного 301 для произвольных старых путей в репозитории нет. JS-редирект и meta refresh не заменяют HTTP 301. **Запуск миграции только на обычном Pages блокируется требованием перенаправлений и сохранения старых маршрутов.**

Минимальное предложение: сохранить текущий Apache и старое Next.js-приложение. Новые 13 путей и ассеты обслуживать статически, согласованные старые URL направлять точечными 301, остальные старые URL продолжать обслуживать старым приложением. Нужны доступ администратора, проверка существующих ProxyPass/RewriteRule и отдельный тестовый vhost. Альтернатива — отдельный edge/reverse-proxy слой с 301 и проксированием старых путей; сам перенос на новый статический хост не решит сохранение контента.

## Реализованная сборка

- `npm run build:launch`: конечный base `/`; Vite собирает клиент и временный серверный модуль; `renderToString` React на этапе сборки формирует HTML всех 13 страниц и 404. На хостинге Node не нужен. Это статический пререндеринг, а не серверный рендеринг на каждый запрос.
- `npm run build`: отдельная сборка для существующего Pages base; страницы помечены noindex, robots запрещает обход, sitemap пуст. Это страховка от индексации копии, не средство приватности. Ничего не опубликовано.
- В браузере сохраняется `createRoot`: клиент монтирует интерактивное приложение поверх заранее сформированного HTML. Гидратация не введена; возможна краткая повторная отрисовка. Без JS контент остаётся доступным; noscript отключает скрытие блоков анимацией. Формы и интерактивные демо без JS не работают.
- Единственный источник метаданных — `src/seo.ts`, использующий существующие описания страниц. Head формируется при сборке и обновляется при клиентских переходах, включая возврат на главную.
- Единое правило: HTTPS, без www, завершающий `/` у страниц, URL без query/hash в canonical. Старый slug `neurobot` сохранён для стабильности; название продукта — «ИИ-агент».
- Title, description, canonical и OG title/description/url уникальны для страниц; общие OG type/site_name/locale и PNG 1200×630. Favicon уже существовал и включён в конечный корень.
- Sitemap содержит ровно 13 индексируемых маршрутов. 404, design-preview и ассеты исключены. robots конечной сборки содержит sitemap на lexicom.ai.
- Wildcard React показывает 404 при клиентской навигации. HTTP 404 обеспечивается хостингом: локальная проверка `node scripts/serve-static.mjs` использует реальный 404 без SPA fallback. Vite preview не является проверкой серверных 404.

## Правила будущего сервера

HTTP и www → HTTPS lexicom.ai; старые пути → согласованная целевая страница сразу, без цепочек; новые пути без `/` и `/index.html` → соответствующий canonical. Не применять глобальный rewrite всех ошибок на index.html с HTTP 200. Не перенаправлять неизвестные адреса на главную. Серверный 404 → `/404.html` со статусом 404. robots и sitemap должны обслуживаться из новой сборки после отдельного разрешения запуска.
