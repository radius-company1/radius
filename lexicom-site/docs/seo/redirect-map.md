## Минимальная серверная реализация

GitHub Pages самостоятельно не подходит для этой миграции. Предпочтителен существующий Apache с сохранением Next.js на неперенесённых URL. `apache-redirects.example.conf` — неактивный пример точных правил для кандидатов; не готовая конфигурация vhost. Перед включением нужно сверить материалы, доступные модули, приоритет ProxyPass/RewriteRule, HTTPS/www и поддержку старых путей. Не менять DocumentRoot так, чтобы старые адреса внезапно стали 404.

Новые страницы: без завершающего `/` и `/index.html` → 301 к URL со слешем. Неизвестные адреса → настоящая 404, не главная. Кандидат старого адреса должен вести непосредственно на конечный HTTPS canonical; проверить отсутствие циклов, цепочек и потери значимых параметров. Все правила проверить GET/HEAD на тестовом vhost. Локальная проверка новых URL не считается проверкой Apache на боевом сервере.
