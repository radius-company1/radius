# Безопасный город Тулы — РАДИУС

Персональный лендинг-презентация: развитие инфраструктурного слоя городской системы видеонаблюдения Тулы и Тульской области.

## Зона ответственности — главное ограничение проекта

РАДИУС отвечает за инфраструктуру **от коммутатора, который принимает видеопоток (включая сам коммутатор),
до вычислений и хранения**. Прикладное ПО, видеоаналитика и **АРМ оператора (звено 10) — вне зоны**.
Конечный сервис — для **государственных ведомств**. Конкретный вендор ПО для Тулы на лендинге не называется.

**В зоне:** коммутаторы · СКЗИ на каналах · серверы и GPU под видеоаналитику · российская виртуализация ·
СХД · видеоархив как ёмкость · ИБП и охлаждение · мониторинг · CMDB · IPAM/DCIM · логи ·
ITSM и координация смежных подрядчиков · изолированные среды без интернета.

**Вне зоны:** сами камеры и их монтаж, прикладное ПО видеоплатформы и аналитики, разработка алгоритмов ИИ,
рабочие места операторов (АРМ), регламенты работы государственных ведомств.

Граница показана на странице четырежды и должна оставаться согласованной при любых правках:

| Где | Как показано |
|-----|--------------|
| Схема в первом экране | Красная рамка `ЗОНА РАДИУС` вокруг коммутатора → СХД/архив; камеры сверху, АРМ и служба внизу вне рамки, вендор ПО справа |
| `#contour`, цепочка из 11 звеньев | `data-zone="in"` (6 звеньев) и `data-zone="out"` (5 звеньев) |
| `#offline`, блок `.instruments` | Мониторинг / CMDB+IPAM / логи и резерв конфигураций |
| `#role`, блок `.scope` | Список «Вне зоны РАДИУС», включая АРМ |

Цифра «шесть звеньев из одиннадцати» в тексте `#contour` завязана на разметку `data-zone`.
Не возвращать АРМ в зону РАДИУС без явной просьбы.

Секция `#action`: алгоритмы — вендоры прикладных решений; РАДИУС задаёт GPU, ёмкость, каналы и latency.

Секция `#drawings`: две проектные схемы (`scheme-cabinets.jpg`, `scheme-racks-rear.jpg`). Первая — концептуальная
компоновка шкафов со штампом проекта «Безопасный город» (стадия П). Вторая — вид сзади с ведомостью по юнитам,
без привязки к городу в подписи. Цифры со штампа (1017 потоков, 457 детекций) **не** переносятся в блок текущего
состояния: там остаются публичные данные 2025 года. Чертежи открываются крупно по клику.

SLA в `#why` — рабочая практика РАДИУС (≥99,8%, реакция в минутах, устранение в часах). Это не утверждённый
контракт по Туле. Цифры Курска (167 хостов, 20 000+ элементов, 13 000+ триггеров, 99,8%, 15 мин, 4 ч)
остаются фактами кейса, не обобщением на Тулу.

Astra Linux / ViPNet — опыт РАДИУС в регионах, не выбранная архитектура для Тулы.

Не называть на публичной странице ЦРТ, МВД и ФСБ: вместо них — «вендоры прикладных решений» и
«государственные ведомства».

## Драматургия

Порядок секций: состояние → масштаб → целевая модель → **проектные чертежи** → единый контур → диагностика отказов →
роль РАДИУС → от видео к действию → защита → региональный опыт → почему РАДИУС →
**результат → как начать → CTA**. Результат стоит перед «как начать», чтобы CTA был прямым
продолжением первого шага, а не повтором через секцию.

Секция `#experience`: все три региона собраны по одной сетке `Состав / Работы / Ситуация` + один вывод.
Кейсы намеренно равновелики по объёму — они показывают разные этапы, а не разные «уровни сложности».

Слово «контур» зарезервировано за главной метафорой (hero, `#contour`, meta, подпись к схеме).
В остальных местах — «периметр», «сегменты», «среда», «состав», чтобы термин не размывался.
