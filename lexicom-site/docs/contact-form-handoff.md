# Подключение заявок Lexicom — передача специалисту

Подготовлено 4 ноября 2026 года. Получатель всех заявок: **info@lexicom-ai.ru**. DNS, действующий сайт и почтовые аккаунты этой работой не изменялись.

## Что передаём

- `server/` — отдельный HTTP-обработчик `/api/contact` на Node.js 24 и Nodemailer 10.3.1, фиксированная версия в lock-файле.
- `server/.env.example` — поля настройки почты и разрешённых сайтов; заполнить только на сервере.
- `server/deploy/` — пример службы systemd и фрагмент Apache для существующего HTTPS-хоста.
- `src/components/ContactForm.tsx` — общая форма на 13 страницах. Включается при сборке через `VITE_CONTACT_ENDPOINT`.
- `server/contract.json` — получатель, ограничения полей и редакция согласия `2026-11-04`. Этот же файл использует клиент.

До подключения endpoint сайт показывает email и телефон. Чтобы включить форму, после приёмки сервера выполнить сборку с адресом обработчика. Отдельная установка сервера не требует замены действующего лендинга.

## 1. Подготовить окружение

Требуются Linux-сервер с Node.js **24**, исходящим доступом к почтовому серверу (465 либо 587), доступ к конфигурации HTTPS lexicom.ai и SMTP-аккаунт, которому разрешена отправка от выбранного адреса. Если хостинг не поддерживает процессы Node.js, разместить этот модуль на отдельном сервере, а `/api/contact` проксировать к нему через защищённый канал; не публиковать порт 8787 в интернет.

Пример установки на сервер со systemd; сначала согласовать пути с его текущей конфигурацией:

```sh
sudo useradd --system --home /opt/lexicom-contact --shell /usr/sbin/nologin lexicom-contact
sudo install -d -o root -g lexicom-contact -m 0750 /opt/lexicom-contact
sudo install -d -o lexicom-contact -g lexicom-contact -m 0700 /var/lib/lexicom-contact
```

Скопировать содержимое каталога `server/` в `/opt/lexicom-contact/` **без node_modules и .env**. Приложение должно быть доступно на чтение службе, но не через веб-сервер. Установить зависимости:

```sh
cd /opt/lexicom-contact
sudo npm ci --omit=dev --ignore-scripts
sudo install -o root -g lexicom-contact -m 0640 .env.example /etc/lexicom-contact.env
```

В `/etc/lexicom-contact.env` заполнить `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM`. `SMTP_FROM` — только email разрешённого отправителя, без имени и угловых скобок. Для порта 465: `SMTP_SECURE=true`; для 587: `false`, с обязательным STARTTLS. Проверка сертификатов включена.

`IDEMPOTENCY_SECRET` сгенерировать командой `openssl rand -hex 32` и сохранить в этом файле. Он подписывает отпечатки заявок для защиты от дублирования; не менять при обычном перезапуске. `DATA_DIR=/var/lib/lexicom-contact`. Директория должна быть вне корня сайта и доступна только службе.

`ALLOWED_ORIGINS=https://lexicom.ai,https://radius-company1.github.io` разрешает основной сайт и Pages. Оставить только реально используемые источники. Не добавлять `*`. `TRUST_LOCAL_PROXY=true` включать только с локальным прокси, который **перезаписывает** X-Real-IP, как в примере Apache. Если перед Apache есть CDN/другой прокси, сначала корректно настроить доверенные IP этого прокси; нельзя доверять произвольному X-Forwarded-For.

SMTP-пароли не помещать в `VITE_*`, исходники, GitHub или переписку.

## 2. Проверить почту и запустить службу

```sh
cd /opt/lexicom-contact
sudo -u lexicom-contact /usr/bin/node --env-file=/etc/lexicom-contact.env index.mjs --check-smtp
sudo install -m 0644 deploy/lexicom-contact.service /etc/systemd/system/lexicom-contact.service
sudo systemctl daemon-reload
sudo systemctl enable --now lexicom-contact
sudo systemctl status lexicom-contact
```

Если Node установлен не в `/usr/bin/node`, заменить путь в команде и service-файле. Проверка SMTP подтверждает подключение и вход, **письмо она не отправляет**. Служба при старте также проверяет почту и не запускается с пустыми настройками.

## 3. Подключить маршрут, сохранив действующий сайт

Добавить фрагмент `deploy/apache-contact.conf` внутрь существующего HTTPS VirtualHost `lexicom.ai`, **перед** общим правилом `ProxyPass /`. Включить модули `proxy`, `proxy_http`, `headers`, если ещё не включены. Проверить конфигурацию штатной командой (`apachectl configtest` / `apache2ctl configtest`), затем reload. Сохранить резервную копию конфига для отката.

Не менять DocumentRoot, DNS, сертификаты и маршруты старого сайта в рамках подключения формы. Старые `/price.php` и `/distributives/documentation.zip` должны продолжать открываться.

Проверить разрешённый CORS-запрос без отправки письма:

```sh
curl -i -X OPTIONS https://lexicom.ai/api/contact -H 'Origin: https://lexicom.ai' -H 'Access-Control-Request-Method: POST' -H 'Access-Control-Request-Headers: content-type'
```

Ожидается 204, `Access-Control-Allow-Origin: https://lexicom.ai`, разрешение POST и Content-Type. Для постороннего Origin — 403. Обработчик доступен только по HTTPS через веб-сервер; порт 8787 слушает 127.0.0.1.

## 4. Включить форму и принять результат

В единственном источнике сайта:

```sh
VITE_CONTACT_ENDPOINT=https://lexicom.ai/api/contact npm run build:launch
npm run verify:launch
```

Для тестовой публикации Pages вместо `build:launch` использовать `npm run build` с тем же `VITE_CONTACT_ENDPOINT`. Никогда не публиковать сборку с `127.0.0.1` или тестовым SMTP. Публикация основного сайта — отдельный согласованный шаг, с проверкой карты старых адресов.

Приёмка после установки:

1. Отправить одну заявку с согласованным служебным контактом. Проверить появление **письма в info@lexicom-ai.ru**, включая папку «Спам». Одного HTTP 200 недостаточно.
2. Проверить текст: организация, имя, телефон/email, задача, страница, продукт/направление, время, редакция согласия и номер заявки. Ответ на письмо должен уходить на контакт посетителя, если он указал email.
3. Убедиться, что SPF/DKIM/DMARC отправляющего домена настроены почтовым администратором и письмо проходит проверку.
4. Проверить пустые поля, отсутствие согласия, ошибочный контакт, потерю сети, повторную отправку после потери ответа. Данные остаются в форме при ошибке; одинаковый `requestId` не создаёт второе письмо.
5. Проверить с телефона, с основной страницы и продуктовой; форма должна показывать «Заявка принята» только после принятия сообщения SMTP-сервером.
6. Сверить фактическое размещение сервера/почты и сроки хранения с опубликованными юридическими документами компании. Юридические тексты этим изменением не переписывались.

## Работа и восстановление

Один процесс сервиса, одна приватная директория состояния. Не запускать несколько экземпляров с общей директорией. Ограничения: 16 КБ на запрос, 20 обращений с IP в час и 200 в час на сервис; дополнительные ограничения можно задать на прокси при необходимости. Защита включает скрытое поле от простых ботов. CORS не заменяет защиту от автоматических клиентов.

Файлы состояния хранятся 30 дней и очищаются при запуске и каждый час. Они содержат HMAC-отпечаток, состояние, время и редакцию согласия — без имени, контакта, текста заявки и IP. Сами заявки хранятся в почте; срок её хранения настраивает компания. Не включать логирование тел POST на прокси. Срок хранения системных журналов настроить по правилам компании; ошибки содержат номер заявки и код, без SMTP-пароля и персональных полей.

`sent` — SMTP принял письмо; `failed` — явный отказ до принятия, можно повторить; `sending`/`uncertain` — результат неизвестен. После сбоя на этапе SMTP нельзя автоматически повторять такие заявки: сначала найти номер заявки в почтовых логах/входящих. Если письмо отсутствует и провайдер подтвердил отказ, специалист может изменить состояние конкретного файла на `failed` при остановленной службе. Не удалять всю директорию состояния ради повторного запуска.

Команды наблюдения: `systemctl status lexicom-contact`, `journalctl -u lexicom-contact --since today`. Реагировать на `contact_error`, перезапуски и исчерпание места в DATA_DIR. После смены почтового пароля обновить приватный env и перезапустить службу.

Откат формы: собрать сайт без `VITE_CONTACT_ENDPOINT` — останутся email/телефон. Откат сервера: вернуть предыдущий фрагмент прокси, проверить конфигурацию, reload; остановить службу. Действующий сайт не требует отключения.

## Проверки в переданном коде

```sh
cd server
npm ci --ignore-scripts
npm test
```

Тесты поднимают HTTP и SMTP только на loopback. Покрыты валидная заявка, неизменяемый получатель, редакция согласия, ошибочные/избыточные поля, запрещённый Origin, лимит запросов, отказ и таймаут SMTP, последовательные и одновременные повторы. Внешняя почта в тестах не используется.

Документация библиотеки: [SMTP и TLS](https://nodemailer.com/smtp), [поля письма](https://nodemailer.com/message).

Конфигурация Apache сверена с документацией: [ProxyPass](https://httpd.apache.org/docs/2.4/mod/mod_proxy.html#proxypass), [RequestHeader](https://httpd.apache.org/docs/2.4/mod/mod_headers.html#requestheader). Проверка конкретного VirtualHost выполняется специалистом на сервере.
